# 前端设计规范

> 所有页面与组件必须遵守。基于 Arc 组件库的设计规则（Arc MCP `get_skill`：`design`、`copy`、`composition`、`accessibility`），
> 针对本项目做了取舍：中文界面、信息密度高的多店后台、主要在出单机（Windows，1366 ~ 1920 宽）上使用。
> 前端结构与组件映射见 [frontend.md](frontend.md)；工程分层见 [engineering-rules.md](../engineering-rules.md) 2.1。审查时按第 11 节逐条核对。

---

## 1. 原则

1. **准确优先**：数据从哪来、是否最新、哪家店没取到，都要让人一眼看出。不确定的数字不显示成确定的。
2. **密度适中**：这是天天用的工作台，不是营销页。表格与列表优先，卡片只用于真正独立的区块。
3. **危险操作有门槛**：取号、发货、作废、改出口这类不可轻易撤回的操作，先预览、再按住确认（第 7 节）。
4. **安静的界面**：大部分区域是中性色；强调色只给「当前选中、进行中、最重要的那个数」；状态色只表示真实状态。
5. **能用组件就不自己画**：先找 Arc 组件 / 区块，只用文档列出的 props，组合写在 `components/custom/`。Arc 源码只在第 2 节说明的那 9 个组件上有改动（同步自壹帆智播），其余不改。

---

## 2. 设计令牌

只用 Arc `foundation.css` 的语义令牌。**禁止**原始色值（hex / rgb）、Tailwind 颜色类、`--neutral-*` 色阶、任意字号。

| 类别 | 令牌 |
|---|---|
| 背景与表面 | `--background`、`--surface`、`--surface-raised`、`--surface-muted` |
| 文字 | `--foreground`（主）、`--text-secondary`（次）、`--text-muted`（弱） |
| 线 | `--border`（默认）、`--border-subtle`（表面内部）、`--border-strong`（输入框、强调） |
| 强调色 | `--accent`、`--accent-strong`、`--accent-subtle`、`--accent-foreground` |
| 状态 | `--success`、`--warning`、`--danger`（信息类用 `--accent`） |
| 图表 | `--series-1` ~ `--series-4` |
| 圆角 | 桌面工具档：`--radius-control` 10、`--radius-panel` 12、`--radius-surface` 16、按钮 `--radius-button` 全圆；嵌套圆角 = 外圆角 − 内边距 |
| 间距 | 4px 网格，`--space-1` ~ `--space-24`；组内 16、区块之间 24、页面内边距 24 |
| 控件高度 | `--control-height-sm` 32（表格内、工具栏）、`--control-height-md` 36（默认）、`--control-height-lg` 48 |

- **主题**：默认浅色，支持深色（`<html data-theme="dark">`）。强调色固定 `data-accent="blue"`。每个页面都要在浅色与深色下检查。
- **阴影**：浮层（菜单、弹出框、对话框、抽屉）用 `--shadow-floating`；侧栏和卡片用轻阴影 `--shadow-resting`。
- **覆盖位置**：以上尺寸与阴影写在 `src/styles.css` 开头的 `:root`（覆盖 `foundation.css`，后者不改）。
- **改过的 Arc 组件**（2026-11-25 从壹帆智播 `ui-next` 同步）：`button`（全圆、图标大小、`iconOnly`、禁用外观）、`dialog`、`input`、`select`、`textarea`、`segmented-control`、`dropdown-menu`（改为 `trigger` + `items`）、`tooltip`、`badge`。Arc 升级时逐个对照合并。
- **指标卡颜色**：名称前一个含义色小圆点（`lib/kpi-tone.tsx`）：蓝 = 要处理的量、黄 = 快到期 / 预警、红 = 已超时 / 异常、紫 = 售后、绿 = 正常、灰 = 中性。黄和红的数为 0 时圆点变灰，只有真出问题才亮。红点有数时向外扩散一圈（1.4 秒一次），其他颜色不动；系统开了「减少动态效果」时也不动。
- **指标卡**：一行胶囊（56 高，名称在左、数字在右，数字 20 号），Arc `metric-card` 和页面里的金额卡 `statCard` 同一个样子；不写说明文字，必要的补充放进名称（如「保证金余额 · 3 家店」）。
- **动效速度**：桌面工具档调快了 Arc 的动效（`motion-tokens.ts` 弹簧 0.16 / 0.22 / 0.2 秒，`--duration-spring` 240ms）。分段切换按钮不做滑动黑底，选中项原地变色（0.12 秒），按钮之间有空隙，滑过去像拖着框。
- **操作结果提示**：同步、探测、检查出口这类结果用右下角浮动提示（`components/custom/notice`，普通 4 秒、报错 8 秒自动消失，同一店同一操作只留一条），不插在页面里推挤表格。读取失败、演练模式、取号 / 发货这类危险操作的报错仍放在页面内。
- **表格单元格**：一行写完，不做上下两行；次要信息放悬停提示（如店铺到期时间显示「剩 N 天」，具体时间悬停看）。行尾只露一个主按钮，其余收进「⋯」。
- **小字说明**：不写解释性的灰色小字（页面说明、卡片副标题、对话框里重复标题的说明）。只保留错误、影响范围、额度消耗这类不看会出错的提示。

## 3. 字体与数字

- **字体栈**（覆盖 Arc 默认，因为 Inter / Geist 不含中文）：
  `--font-body: Inter, "PingFang SC", "Microsoft YaHei", "Noto Sans SC", system-ui, sans-serif`；
  `--font-display` 同上（中文标题不用 Geist）。数字与英文仍由 Inter 渲染。
- **字号**只用刻度：12 / 13 / 15 / 17 / 20 / 22 / 28。表格正文 13，表头 12，页面标题 20 或 22。输入框文字 14（`--text-field`）。
- **字重**只用 400 与 500，层级靠字号、颜色与间距。禁止 600 / bold、全大写、标题上方的小字标签（eyebrow）。
- **会变化或要对齐的数字**（金额、数量、计数、时间）一律 `font-variant-numeric: tabular-nums`，表格中右对齐。

---

## 4. 布局

- **外壳**：浅灰底上的浮动侧栏（固定宽、不收起，左下角个人中心）+ 内容区。全应用只有一个页面容器，区块不再自带外边距或最大宽度。
- **侧栏**（从上到下）：品牌 → 店铺范围（多选，空 = 全部店铺）→ 分组导航 → 任务中心 → 个人中心（主题、修改密码、退出登录）。
- **页面标题行**：左边页面标题，右边会话健康指示。
- **内容区**：页面标题 + 一行主操作 → 筛选工具栏 → 计数条 / 指标 → 主表格。每个页面只有一个主按钮（Arc `button` 默认 `primary`，其余设 `secondary` 或 `ghost`）。
- **宽度**：主要适配 1366 与 1920；在 1024 下不能横向滚动页面；宽表格只在自身卡片内横向滚动，首列（店铺 / 订单号）固定。
- **表格密度**：行高 44；勾选、批量操作的表格允许紧凑模式（行高 36）。表头吸顶。

## 5. 状态的颜色与文案

状态标记用 Arc `badge`，颜色只放在图标与浅底上，**必须配文字**。同一含义全站同一写法：

| 对象 | 状态 | 色调 | 文案 |
|---|---|---|---|
| 店铺会话 | `active` + healthy | success | 正常 |
| | `active` + expiring | warning | 即将过期（剩 N 天） |
| | `needs_login` | danger | 需重新登录 |
| | `disabled` | neutral | 已停用 |
| 店铺暂停 | `paused_reason` 非空 | danger | 风控暂停 |
| 出口 | `unchecked` | neutral | 未检查 |
| | `ok` | success | 出口正常 · 1.2.3.4 |
| | `unreachable` | danger | 出口不通 |
| | `changed` | warning | 出口 IP 已变为 1.2.3.5，需确认 |
| | `duplicate` | danger | 出口 IP 与其他店重复 |
| | 代理剩 ≤ 7 天 | warning | 代理 N 天后到期 |
| 订单（本地） | `synced` / `pending_label` | neutral | 待处理 / 待打单 |
| | `label_obtained` / `printed` | info（accent） | 已打单 / 已打印 |
| | `shipped` | success | 已发货 |
| | `exception` | danger | 异常（悬停显示原因） |
| | `cancelled` / `closed` | neutral | 已取消 / 已关闭 |
| 数据来源 | 某店上游失败 | warning | N 家店未取到（可展开看是哪几家及原因） |

- 绿色不是「好看」，红色不是「重要」：只在成功、需要注意、失败时使用。
- 平台状态与本地状态同时出现时，平台状态用中性文字，本地状态用 `badge`。

## 6. 数据格式

| 数据 | 格式 | 例 |
|---|---|---|
| 金额（整数分） | `¥` + 千分位 + 两位小数 | `¥1,234.56`、`-¥5.00` |
| 时间 | 北京时间 `YYYY-MM-DD HH:mm`；今天的只显示 `HH:mm`；悬停显示完整时间 | `2026-11-25 08:30` |
| 剩余时间 | 「剩 N 天 / N 小时」，过期显示「已过期」 | 剩 3 天 |
| 订单号、运单号 | 等宽数字，点击可复制，复制后就地显示「已复制」 | |
| 脱敏字段 | 原样显示平台给的脱敏值，不再二次处理 | `张*`、`138****0000` |
| 空值 | 「暂无」，不用 `-` 或 `—` | |
| 商品摘要 | 首个商品名 + 「等 N 件」（N 为商品行数） | 商品甲 等 3 件 |

## 7. 交互

- **四种数据状态**：每个数据区都有 加载中（Arc `skeleton`，保持布局不跳动）、空（Arc `empty-state`，说明原因并给出下一步）、出错（区块内 `alert`，写明原因与重试按钮）、成功（就地反馈）。不能只靠 toast 告知前台操作的结果。
- **部分店铺失败**：不让整页报错；在计数 / 表格上方显示「N 家店未取到」的 warning 条，其余店的数据照常显示。
- **实时更新**：SSE 推来的变化直接刷新对应区域，不弹窗；正在操作（勾选、填写）的表格不因刷新丢失选择。
- **筛选**：店铺筛选、状态筛选、页码都同步到 URL，刷新与分享后保持；切换筛选回到第 1 页。
- **危险操作**：先打开预览（列出将影响的店铺与订单数），再用 Arc `hold-to-confirm` 按住确认；演练模式下确认按钮禁用并标注「演练模式」。改出口、恢复风控暂停也需要确认对话框。
- **等待外部动作**：扫码登录等需要用户在别处操作的流程，显示明确的等待态（说明去哪里做什么），并有超时与失败提示。
- **按钮可用性**：不可用的按钮保持可见但禁用，悬停说明原因（例如「出口未检查通过，不能扫码」）。

## 8. 文案（中文）

- 按钮用动词开头、两到四个字：「扫码登录」「检查出口」「同步订单」，不用「确定」「提交」这类泛词（对话框的取消除外）。
- 句末不加句号；不用感叹号；不用破折号（用逗号、冒号或括号）。
- 错误提示 = 发生了什么 + 怎么办：「出口不通，请检查代理是否到期或更换代理」，不写「操作失败」。
- 中文与数字、英文之间加空格：「剩 3 天」「出口 IP」。
- 术语全站统一：店铺、出口、代理、扫码登录、取号、面单、发货、对账、风控暂停。不混用「门店」「线路」「节点」等。

---

## 9. 图标

- `lucide-react`，16 / 20 / 24 px，`strokeWidth={1.75}`；装饰性图标加 `aria-hidden="true"`。
- 图标放在文字旁边，不放进圆形或方形底块（除非它本身就是控件或表示状态）。
- 危险或不常见的操作用文字按钮，不只用图标。

---

## 10. 可访问性与键盘

- 键盘焦点只用 Arc `foundation.css` 自带的 `:focus-visible` 样式，不自己加外框或光晕，鼠标点击不显示焦点框。
- 表格支持 ↑ ↓ 移动、空格勾选；对话框可用 Esc 关闭、焦点留在对话框内。
- 状态不能只靠颜色区分，必须有文字（第 5 节）。
- 动效用 Arc `motion-tokens`，只动 transform 与 opacity，并提供减少动效时的分支；不做循环动画。

## 11. 审查清单

每个前端任务提交审查前自查，管理者按此核对：

1. 没有原始色值、Tailwind 颜色类、600 以上字重、刻度外字号、全大写、破折号
2. 先用 Arc 组件；只用文档列出的 props；没有改 `components/arc/` 源码
3. 每个数据区都有加载、空、出错三种状态；部分店铺失败有 warning 条
4. 状态标记符合第 5 节的色调与文案
5. 金额、时间、空值符合第 6 节；数字列 `tabular-nums` 且右对齐
6. 每个页面只有一个主按钮；危险操作走预览 + 按住确认
7. 浅色、深色各截一张图检查；1024 / 1366 / 1920 下没有页面横向滚动
8. 文案符合第 8 节；术语统一
9. 分层符合 engineering-rules 2.1（`logic` 不引 react、`components` 不调接口、`index.tsx` ≤ 80 行）
