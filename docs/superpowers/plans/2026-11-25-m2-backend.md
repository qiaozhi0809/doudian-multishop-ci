# M2 后端：取号、作废、打单并发货、按需解密 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans（本计划由当前会话内联执行，逐任务 TDD）。
> 步骤用 `- [ ]` 记录；每个任务一个提交，提交信息用任务末尾给出的那一条。

**Goal:** 两步提交的取号编排（打面单 / 打单并发货）、面单作废、取号超时后的查回恢复、按需解密收件人，
并把这些能力经本地 API 与 SSE 暴露给打单台。

**Architecture:** 仍按 `api → service → adapter / store / domain`。所有抖店请求经 `ShopRunner.run`（出口 → 每店串行 → 审计）。
抖店写接口逐接口在 `endpoints.py` 声明（`write=True`），协议体构造放 `adapter/doudian/label_request.py`，
响应解析放 `adapter/doudian/label_parsers.py`。取号前置判断与账户选择是纯函数（`domain/labeling_rules.py`），幂等键在 `domain/idempotency.py`。
两步提交：`preview` 只读本地并生成短期预览（10 分钟、一次性），`execute` 才入队发写请求；预览与执行之间订单状态变化时重新校验并跳过。

**Tech Stack:** 同 M1；无新增依赖。

## Global Constraints

- 依赖方向与文件长度：同 M1（`*.py` ≤ 400 行）。
- **取号不解密**（DEC-06）：取号与一体接口链路不得调用 `receiveinfo`；解密只由用户显式查看触发。
- 写接口 `write=True`，客户端不自动重试；超时 / 结果不明的取号**不得**转 `exception`，走「待核实 → 查回运单号」。
- 幂等键：取号 / 一体 `label:{shop_id}:{order_no}:{seq}`（`seq` = 已作废面单数 + 1）；作废 `void:{shop_id}:{courier_code}:{waybill_no}`。
- 金额整数分；时间 ISO-8601 UTC；地址、模板、账户只按 `(shop_id, code)` 取，**禁止跨店复用**。
- 账户选择（DEC-05 建议稿）：可用账户中 `isDefault=true` → `balance` 最大；`balance=0` 拦截，`-1`（月结）视为可用。
- 预览 10 分钟有效、一次性；`dry_run` 下 `execute` 一律拒绝。
- 测试 fixture 不出现真实手机号 / cookie / token；写接口样本按 A.2 已记录的请求与响应结构构造（无真实商家自发单可抓，gaps API-04）。

## Review Focus

1. **重复执行**：同一预览重复 `execute`、或网络重试 → 任务行按幂等键复用，`waybills` 的 `uq_active_waybill` 兜底，不产生第二张有效面单。
2. **取号超时**：`TransientError` 或 `fail_msg` 含「不存在可取号商品」→ 订单保持 `pending_label`、任务 `verifying`，查回成功则补写面单。
3. **作废后重取**：`seq` 递增使幂等键不撞旧键，`uq_active_waybill` 允许新面单。
4. **解密风控**：`602502151` 只暂停该店解密（3 小时冷却），**不暂停该店**；连续解密间隔 ≥ 2 秒；明文只在内存缓存到 `expire_time`。
5. **预览漂移**：预览后被平台关闭 / 已在别处取号的订单在执行时跳过并报告原因，不阻塞同批其他单。

### Task 5: 执行（第③步）：取号 / 一体 / 作废 / 查回恢复

**Files:** Create `backend/app/service/labeling.py`、`backend/app/service/label_recovery.py`；Modify `backend/app/wiring.py`；
Test `backend/tests/service/labeling_test.py`

**Interfaces:**
- `LabelingService(engine, runner, previews, events, tasks_registry, settings, clock)`：
  `execute(preview_id, actor) -> LabelExecuteStarted`（`dry_run` → `DryRunBlocked`；后台任务名 `labels-<preview_id>`）；
  执行前重新校验（本地状态、平台状态、`combine_id`、已存在有效面单），不通过的单跳过并报原因
- 逐店串行：`PRODUCT_TYPES` → 取号 / 一体 → 解析 → 成功写 `waybills(active)` + 订单 `label_obtained` / `shipped`；
  `BizRejected` → 订单 `exception` + 原因；`TransientError` / 「不存在可取号商品」→ `recover_label` 查回（`ORDER_LOGISTICS`），
  查到补写面单并推进状态，查不到任务 `verifying`、订单保持 `pending_label`
- 作废：按面单调用 `CANCEL_TRACKING_NOS`，成功 `waybills.status=void`、订单回 `pending_label`（`shipped` 的单不允许）
- SSE：`label_progress {preview_id, mode, shop_id, order_no, result, tracking_no?, reason?}`、`label_done {preview_id, ok, failed, verifying}`
- 幂等：每单先 `task_store.start`，已 success 直接复用结果

- [ ] Step 1: 写失败测试：成功路径、业务拒绝、超时→查回成功 / 未查到、重复执行不产生第二张面单、作废后重取 `seq=2`、一体直达 `shipped`
- [ ] Step 2~4 → Step 5: Commit — `feat(service): 取号执行、作废与超时查回`
