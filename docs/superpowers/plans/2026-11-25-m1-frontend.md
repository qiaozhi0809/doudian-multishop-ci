# M1 前端：App Shell、店铺页、订单列表 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 提供管理员初始化与登录、后台外壳（侧边栏 + 顶栏店铺筛选 + 会话健康指示）、店铺与设置页（添加、扫码登录、探测、基础数据与就绪状态）、跨店订单列表（计数 tab、筛选、分页、手动同步）。

**Architecture:** React 19 + Vite。每个页面按 engineering-rules 2.1 分 `logic/`（纯函数）、`hooks/`（数据与状态）、`components/`（纯展示）、`index.tsx`（装配，≤ 80 行）。
服务端状态全部用 TanStack Query；接口类型由 openapi-typescript 从后端 `openapi.json` 生成；SSE 事件让对应查询失效。

**Tech Stack:** pnpm、React 19、TypeScript、Vite、Tailwind CSS 4、Arc（Free 优先）、TanStack Query、React Router、openapi-typescript、Vitest、Testing Library。

**Spec:** [design/frontend.md](../../design/frontend.md)、[design/local-api.md](../../design/local-api.md)、[engineering-rules.md](../../engineering-rules.md) 2.1 / 第三节 / 第七节。
后端接口来自 [M1 后端计划](2026-11-25-m1-backend.md) Task 12、Task 13。

**前置条件：** 本机已按 frontend.md 第 7 节配置 Arc 组件库（`@uiarc` / `@uiarc-pro` registry）；后端已导出 `frontend/openapi.json`。

## Global Constraints

- 目录：`frontend/src/components/{ui,arc,custom}`、`frontend/src/pages/<module>/{logic,hooks,components,index.tsx}`、`frontend/src/lib/`。
- `logic/*.ts` 不得 import react；`hooks/` 不返回 JSX；`components/` 不调 fetch / API；`index.tsx` ≤ 80 行；`*.ts(x)` ≤ 300 行；文件名 kebab-case。
- Arc 优先于自建、Free 优先于 Pro；Arc 源码安装进 `components/arc`，不改其源码，组合写在 `components/custom`。
- 本地 API 分页 `page` 从 1 开始；金额字段为整数分，展示时换算为元；时间字段为 ISO UTC，展示按北京时间。
- 错误响应为 `{"error": {"type", "message", "shop_id", "detail"}}`。
- 开发服务器 `localhost:5173`，代理 `/api` 到 `http://127.0.0.1:8787`。

## Review Focus

1. **部分店铺计数失败**（`/api/orders/counts` 中某店 `source: "error"`）→ 合计旁显示「N 家店未取到」，不能把失败店当 0 静默合计。（Task 6）
2. **金额换算**：`0`、`1`、`123456`、负数都正确显示为元（`¥0.00`、`¥0.01`、`¥1,234.56`、`-¥5.00`）。（Task 2）
3. **浏览器时区不是北京时间**：同一 ISO 时间在任意时区下都显示为北京时间。（Task 2）
4. **SSE 断线重连**后，店铺与订单查询重新拉取，避免停留在旧状态。（Task 2）；会话过期后任意请求返回 401 时跳回登录页，登录后回到原页面（Task 3）
5. **还没有任何店铺**时，订单页与店铺页显示引导添加店铺的空状态，而不是空表格。（Task 5、6）

**Interfaces:**
- Consumes: `GET /api/auth/status`、`POST /api/auth/setup|login|logout|password`（后端 Task 13）
- Produces:
  - `resolveAuthRoute(status: {setup_required, logged_in}, path: string) -> string | null`：需要初始化 → `/setup`；未登录 → `/login?next=<path>`；已登录却在 `/login` 或 `/setup` → `next` 或 `/orders`；否则 `null`（不跳转）
  - `useAuth(): { status; login(u, p); setup(u, p); logout(); changePassword(old, new) }`
  - `api-client` 收到 401 → 清空查询缓存并跳 `/login?next=<当前路径>`
  - 登录页用 Arc `sign-in`（或 `login-split`）；错误码 423 显示「尝试次数过多，请 5 分钟后再试」；密码少于 8 位时在提交前提示

- [ ] **Step 1: 写失败测试**

  - `route_login_with_next`：未登录访问 `/shops?shops=1` → `/login?next=%2Fshops%3Fshops%3D1`
  - `route_logged_in_on_login`：已登录在 `/login?next=/shops` → `/shops`
  - `unauthorized_redirects`：模拟接口返回 401 → 跳转到 `/login?next=...`，查询缓存被清空
  - `locked_message`：登录返回 423 → 表单显示锁定提示
- [ ] **Step 2 ~ 4: 运行失败 → 实现 → 运行通过**；顶栏右上角显示当前用户名与「退出」「修改密码」（在 Task 4 的 App Shell 中接入）
