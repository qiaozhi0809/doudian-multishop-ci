# M2 前端：打单台 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans（当前会话内联执行，逐任务 TDD）。

**Goal:** 打单台页面：跨店待取号订单池、筛选与勾选、取号 / 打单并发货两个两步提交入口（预览 → 按住确认 → 执行）、
已取号面单查看与面单作废、按需查看收件人（含额度冷却提示）。

**Architecture:** 按 engineering-rules 2.1 的 `logic / hooks / components / index.tsx` 四层；
服务端状态用 TanStack Query，执行进度用 SSE（`label_progress` / `label_done`）失效查询；危险操作使用 Arc `hold-to-confirm`。

**Tech Stack:** 同 M1；新增复制 Arc `hold-to-confirm`、`checkbox` 两个组件到 `components/arc/`。

**Spec:** [design/frontend.md](../../design/frontend.md)、[design/ui-guidelines.md](../../design/ui-guidelines.md)、
[design/local-api.md](../../design/local-api.md)、[flows.md](../../design/flows.md) 7.3、[engineering-rules.md](../../engineering-rules.md)。
后端接口来自 [M2 后端计划](2026-11-25-m2-backend.md) Task 7。

## Global Constraints

- `logic/*.ts` 不 import react；`hooks/` 不返回 JSX；`components/` 不直接调 API；`index.tsx` ≤ 80 行；`*.ts(x)` ≤ 300 行。
- Arc 优先、Free 优先；复制进 `components/arc` 不改源码，组合写 `components/custom`。
- 金额整数分展示换算；时间按北京时间；状态文案按 ui-guidelines 第 5 节。
- 预览对话框按店分组列出将影响的订单与阻断原因；演练模式下确认按钮禁用并标注「演练模式」。
- 执行结果就地反馈（SSE 汇总条 + 每单结果），不只靠 toast。

## Review Focus

1. **勾选不丢失**：SSE 刷新 / 执行完成后，正在勾选的表格不丢选择；已执行成功的单从可勾选集合移除。
2. **阻断原因可见**：缺 `combine_id` / `sku_id` 的订单在池中禁用勾选并悬停说明（gaps API-04 的真实表现）。
3. **危险操作**：取号、一体、作废都必须经过预览 + 按住确认；演练模式不可执行。
4. **解密冷却**：429 时显示「该店解密冷却中，约 3 小时后恢复」，不重试、不影响取号。
