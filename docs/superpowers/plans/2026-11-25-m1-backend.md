# M1 后端：基础 + 只读订单 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 本机管理员登录；多店扫码登录、会话加密保存与探测、基础数据同步、待发货订单定时同步入库，并通过本地 API 与 SSE 提供给前端。

**Architecture:** `backend/app/` 按 `api → service → adapter / store / domain` 分层（engineering-rules 2.2）。抖店请求只经
`adapter/doudian/client.py` 的 `FxgClient`，发送层 `Transport` 可替换，测试用 `FakeTransport` 回放 JSON 样本。
SQLite + SQLAlchemy 2 Core，Alembic 管迁移。后台任务用 asyncio：每店一把锁、全局信号量 3。

**Tech Stack:** Python 3.12、uv、FastAPI、Pydantic v2、curl_cffi、Playwright、SQLAlchemy 2 Core、Alembic、structlog、
cryptography、argon2-cffi、pywin32（仅 Windows）、pytest、pytest-asyncio、ruff。

[design/data-model.md](../../design/data-model.md)、[design/flows.md](../../design/flows.md) 7.1 / 7.2 / 第 8 节、

## Global Constraints

- 目录与依赖方向按 engineering-rules 2.2 / 第七节；`domain/` 不得 import fastapi / sqlalchemy / curl_cffi 或做 IO。
- 文件硬上限：`*.py` 400 行；文件名 snake_case；禁止 `utils.py` / `helpers.py` / `common.py`。
- 字面量只在定义源出现：接口路径与分页基准 → `adapter/doudian/endpoints.py`；`_bid` → `bid.py`；错误码 → `error_codes.py`。
- 抖店基址 `https://fxg.jinritemai.com`；公共参数 `appid=1`、`aid=4272`、`_bid`（`ffa_order` / `ffa_goods` / `ffa_aftersale`）、`__token`、`_lid`（随机 12 位数字）。
- 成功码为 `0` 或 `"100000"`；`code=10008` 即会话失效。
- `searchlist`：GET，`page` 从 0 开始，`pageSize` ≤ 200，`tab` 与 `order_status` 必须同时传。`getAfterSaleList`：`page` 从 1 开始。`expressList` 必须 POST。
- 同店请求串行，间隔随机 300 ~ 1200 ms；全局同时最多 3 个店。
- 会话有效期 60 天；到期前 7 天为 `expiring`。探测每 30 分钟，订单同步每 5 分钟。
- 金额一律整数分；时间存 ISO-8601 UTC；业务日期按北京时间（UTC+8）。
- cookie、`__token` 只以密文落库；日志与审计中 cookie / token / 手机号 / 地址一律脱敏。
- 后端只监听 `127.0.0.1:8787`；除登录相关接口外所有 `/api/*` 需管理员会话（backend 5.16）。本地 API 分页为 `page`（从 1 开始）+ `page_size`；错误统一为 `{"error": {"type", "message", "shop_id", "detail"}}`。

## Review Focus

1. **分页中途会话失效**：第 3 页返回 `10008` → 该店标 `needs_login`、已入库的前两页保留、其他店照常同步。（Task 10）
2. **平台时间字段格式不确定**（unix 秒、数字字符串或「YYYY-MM-DD HH:MM:SS」北京时间）→ 都能解析为 UTC ISO。（Task 2）
3. **订单在两次同步之间离开「待发货」tab**（被关闭或在别处发货）→ 按订单号补查：已关闭的本地转 `cancelled`，已发货的只更新 `platform_status`。（Task 10）
4. **店铺没有默认发货地址或面单账户** → 基础数据同步成功，但 `/api/shops` 中该店 `ready_for_label=false` 并给出原因。（Task 9、12）
5. **成功码类型漂移**（`"0"`、`100000` 整数）与未知业务码 → 前者算成功，后者抛 `BizRejected`，不抛未处理异常。（Task 5）

## 样本数据说明

各接口的响应字段以本地 `artifacts/`（不入库）中的实测样本为准。写测试 fixture 时从样本**脱敏后**裁剪到
`backend/tests/fixtures/doudian/<endpoint>.json`；姓名、手机号、地址、cookie、token 一律换成占位值。
`searchlist`、`expressList`、`searchTemplates` 的顶层结构 [api/](../../api/README.md) 未完整记录，以样本为准，并把确认结果补进 `api/read.md`。
