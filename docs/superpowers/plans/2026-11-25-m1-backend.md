# M1 后端：基础 + 只读订单 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 本机管理员登录；每店独立 profile + 固定独立出口；多店扫码登录、会话加密保存与探测、基础数据同步、待发货订单定时同步，并通过本地 API 与 SSE 提供给前端。

**Architecture:** `backend/app/` 按 `api → service → adapter / store / domain` 分层（engineering-rules 2.2）；adapter 与 store 只依赖 domain。
抖店请求只经 `adapter/doudian/client.py` 的 `FxgClient`，发送层 `Transport` 可替换，测试用 `FakeTransport` 回放脱敏样本。
所有会请求抖店的操作都经 `service/shop_runner.py` 的 `ShopRunner.run`：先检查出口与暂停状态，再进该店串行队列。SQLite + SQLAlchemy 2 Core + Alembic。

**Tech Stack:** Python 3.12、uv、FastAPI、uvicorn、Pydantic v2、pydantic-settings、curl_cffi、Playwright、SQLAlchemy 2 Core、Alembic、structlog、
cryptography、argon2-cffi、pywin32（仅 Windows）、pytest、pytest-asyncio、ruff。

**Spec:** [design/backend.md](../../design/backend.md) 5.0 ~ 5.4 / 5.7 / 5.9 / 5.12 ~ 5.17、[design/data-model.md](../../design/data-model.md)、
[design/flows.md](../../design/flows.md) 7.1 / 7.2 / 第 8、9 节、[design/local-api.md](../../design/local-api.md)、[api/read.md](../../api/read.md)、
[api/order-page.md](../../api/order-page.md) C.1 ~ C.3、[engineering-rules.md](../../engineering-rules.md)。路线图：[2026-11-25-roadmap.md](2026-11-25-roadmap.md)。

## Global Constraints

- 依赖方向：`api → service → adapter / store / domain`；adapter、store 只 import domain / shared；`api/` 不 import sqlalchemy 或 `app.store`；`domain/` 不做 IO。
- 文件 `*.py` ≤ 400 行，snake_case，禁止 `utils.py` / `helpers.py` / `common.py`。测试文件按 engineering-rules 2.2 命名为 `<name>_test.py`（pytest 配置同时收集 `test_*.py` 与 `*_test.py`）。
- 字面量只在定义源：接口路径、固定参数、分页基准 → `adapter/doudian/endpoints.py`；`_bid` → `bid.py`；错误码 → `error_codes.py`。
- 抖店基址 `https://fxg.jinritemai.com`；公共参数 `appid=1`、`aid=4272`、`_bid`、`__token`、`_lid`（随机 12 位数字）。成功码 `0` 或 `"100000"`（比较前转字符串）；`10008` = 会话失效。
- `searchlist`：GET，`page` 从 0 开始，`pageSize` ≤ 200，`tab` 与 `order_status` 必须同时传（全部订单时 `order_status=` 空串）。`tabcnt` 固定带 `tabcnt_version=v1&tab=all`。`getAfterSaleList` 的 `page` 从 1 开始。`expressList` 必须 POST。
- 同店请求串行、间隔随机 300 ~ 1200 ms；全局同时最多 3 个店。只读接口遇 `TransientError` 指数退避最多 3 次（backend 5.12）。
- 每店固定出口（backend 5.17）：扫码浏览器、协议通道、浏览器兜底都走该店出口；只接受 `http(s)://` 代理；最多一家 `direct`；出口 IP 唯一；出口异常或风控暂停时跳过该店，**禁止退回直连**；不伪造设备参数，协议通道用扫码浏览器记录的 UA 与 `sec-ch-ua*`。
- 会话 60 天、剩 ≤ 7 天为 `expiring`；探测每 30 分钟；订单同步每 5 分钟。
- 金额整数分；时间存 ISO-8601 UTC；业务日期按北京时间。cookie、`__token`、代理 URL 只以密文落库；日志与审计一律经 `redact_mapping`。
- 只监听 `127.0.0.1:8787`；Host 白名单 `127.0.0.1:8787`、`localhost:8787`（`dev_mode` 加 `localhost:5173`）；除 `/api/health` 与 `/api/auth/status|setup|login` 外均需管理员会话。
- 本地 API 分页 `page` 从 1 开始 + `page_size`；错误信封 `{"error": {"type", "message", "shop_id", "detail"}}`。
- 测试与 fixture 中不出现真实手机号、cookie、token：手机号用 `138****0000` 这类占位，token 用 `"tok_" + "x" * 8` 这类运行时拼接值。

## Review Focus

1. **分页中途会话失效**：第 2 页返回 `10008` → 该店 `needs_login`，第 1 页已入库，其他店照常。（Task 12）
2. **平台时间字段格式不确定**（unix 秒、数字字符串、「YYYY-MM-DD HH:MM:SS」北京时间）→ 都解析为 UTC ISO。（Task 2）
3. **订单离开「待发货」**（被关闭或在别处发货）→ 按订单号补查一次：关闭转 `cancelled`，已发货只更新平台状态且以后不再补查。（Task 12）
4. **代理挂了 / IP 变了 / IP 重复** → 该店暂停并说明原因，没有任何请求经直连发出，其他店照常。（Task 9、10）
5. **触发风控**（`RiskBlocked`）→ 该店写入 `paused_reason` 并停止定时请求，直到人工恢复；不会每 5 分钟继续撞。（Task 10）

### Task 7: 扫码登录（浏览器通道）
